# Data sources — YouTube metadata without the Data API

Written 2026-09-18. This is the research file behind `shared/seed/lofi-feed.json`, the
provider layer in `prototype/src/youtube.js` and `ios/LofiGlass/Services/`.

> **Honesty about verification.** This sandbox reaches `registry.npmjs.org` and nothing
> else: every `curl` to a YouTube or mirror host returned `000`. Two things were therefore
> observed **live through the page-fetch tool** (marked 🟢), and everything else is the
> documented shape of the API reproduced from vendor docs and my own knowledge (marked 🟡).
> The code treats every live source as best-effort and always has the seed corpus to fall
> back to, so an unverified shape can't break the app — it degrades to the seeded path.
> Re-run the probes in [§8](#8-re-running-the-probes) from a networked machine before you
> trust any 🟡 row.

---

## 0. What we are actually trying to get

| need | where it lives | used for |
| --- | --- | --- |
| candidate videos for a query | search endpoint | the deck |
| title, channel name/handle/id | search + `videos.list?part=snippet` | card face, credit line |
| duration, view count, publish date | `videos.list?part=contentDetails,statistics` | mix-vs-track UI, freshness, gate scoring |
| description (tracklists, hashtags, socials) | `snippet.description` | credits sheet, tags, "artist at this timecode" |
| top comments | `commentThreads.list?part=snippet` | the comment block in the info sheet |
| playback | YouTube's own iframe player (`youtube.com/embed/{id}`) | the deck |
| **audio samples for a local DSP boost** | **nowhere legal, publicly** | the iOS "local boost engine" route |

The last row is the only hard one, and it drives the whole architecture.

## 1. 🟢 Watch page — what metadata is exposed (observed)

`fetch_page` on a watch URL returns the *rendered* page, which is enough to confirm the
fields exist and in what format. Real values pulled during this session:

| video | id | duration | notes |
| --- | --- | --- | --- |
| lofi hip hop radio – beats to relax/study to (Lofi Girl) | `jfKfPfyJRdk` | live, 24 738 watching | description carries a promo block + hashtags `#lofi #chill #study` |
| FEN – "The Last Sunset" (Full Instrumental) | `m772TdT9uny` | 3:57 | `Provided to YouTube by DistroKid`, `℗ 2024 …`, `Released on: 2024-07-19`, `Auto-generated by YouTube.` |
| lofi hip hop radio 📚 – beats to relax/study to | `P31G_H6domU` | 3:37:02 | `Stream + Download 👉`, `🔔 Subscribe … to become a Lofi Girl`, `Tracklist:`, `Visual: …` |

Formats that matter for the parser:

- **timestamps** — `0:00 Title`, `3:40 Artist - Title`, `[01:02:03] artist - title`,
  `0:00 Sutton – Lunch Break` (en dash), `0:00 Artist — Title` (em dash), `•` and `·`
  separators, `Title by Artist` order.
- **producer noise** to strip: `prod. X`, `beat by X`, `lyrics by X`, `mixed by X`.
- **link noise** to reject outright: lines starting `listen`, `subscribe`, `follow`,
  `merch`, `shop`, `download`, `stream`, `contact`, `booking`, `instagram`, `spotify`,
  `apple music`, `submit`, `discord`, `patreon`, `promo`, `copyright`, `all rights reserved`.
- **hashtags** — always a trailing block; they are the cheapest real tagging signal and
  they survive into every description-based fallback, so `TracklistParser.hashtags(in:)`
  exists in both languages rather than being an afterthought.

`watch?v=` pages are **not** a data source you should scrape in a shipping app (the markup
changes, the ToS frowns on it, and the JSON blob is `ytInitialData`, not an API). They are
useful for confirming shapes, which is all they were used for here.

## 2. 🟢 Search results page — what a query yields (observed)

`https://www.youtube.com/results?search_query=lofi+hip+hop+mix` rendered real, current
results with the fields we need (title, channel, duration, views, relative age). Two
observations that changed the design:

1. **Duration is a first-class part of the label** ("3:37:02", "LIVE") — the UI must carry
   it or mixes look broken.
2. **The genre is noisy.** Search results for "lofi mix" include deep-house festival mixes
   and workout playlists. Hence the gate in [§6](#6-the-lofi-gate-a-score-you-can-defend),
   not a prayer that `videoCategoryId=10` means anything.

## 3. 🟡 YouTube Data API v3 — the sanctioned path

`GET https://www.googleapis.com/youtube/v3/<resource>?key=<API_KEY>&…`

| endpoint | params that matter | response path we read | quota |
| --- | --- | --- | --- |
| `search.list` | `part=snippet`, `q`, `type=video`, `videoCategoryId=10` (Music), `relevanceLanguage=en`, `order=viewCount` (mood) / `date` (freshness), `maxResults≤50`, `safeSearch=none`, optional `publishedAfter=YYYY-MM-DDThh:mm:ssZ` | `items[].id.videoId`, `items[].snippet.{title,channelTitle,channelId,publishedAt,thumbnails.medium.url,description}` | **100** |
| `videos.list` | `part=snippet,contentDetails,statistics,status`, `id=<up to 50 csv>` | `contentDetails.duration` (ISO-8601), `.caption`; `statistics.viewCount`, `.likeCount`; `snippet.tags[]`, `.description`; `status.embeddable` | **1** |
| `commentThreads.list` | `part=snippet`, `videoId`, `order=relevance`, `maxResults≤100`, `textFormat=plainText`, `pageToken` | `snippet.topLevelComments[].id`, `.snippet.{authorDisplayName,authorProfileImageUrl,likeCount,publishedAt,isAuthor,viewerIsAuthor}` + `.snippet.textDisplay` / `textOriginal`, `snippet.totalSearchResults`, `nextPageToken` | **1** |
| `channels.list` | `part=snippet,brandingSettings,contentDetails`, `id` | follower counts, banner, `contentDetails.relatedPlaylists.uploads` | **1** |

Notes that are easy to get wrong:

- `search.list` is expensive and returns only 5 results by default — always pass
  `maxResults` explicitly and batch the ids into **one** `videos.list` call.
- `search.list` snippets carry **no** `viewCount` and **no** duration; you must make the
  second call to know whether something is a 40-minute mix or a 3-minute single. Our
  `YouTubeDataProvider` does exactly that, then one `commentThreads.list` per detail fetch.
- ISO-8601 durations are not parseable with `DateFormatter` on iOS — there is a hand-rolled
  `duration(fromISO8601:)` (`PT1H2M3S` → 3723) in `YouTubeDataProvider.swift`, and the
  same math in `youtube.js`. Live streams report `PT0S`, which the UI must show as LIVE.
- Quota is **10 000 units/day** by default. Per search, a full loop
  (100 + 1 + 1 ≈ 102 units) buys 21 decks of metadata a day, which is a lot.
  `comments.list` is never used — `commentThreads.list` already gives top-level comments
  sorted by relevance and is the cheaper way to do it.
- `videos.list` on a video with comments disabled returns an empty
  `commentThreads` list, not an error. Treat empty as "no comments", not "no data".
- Keys belong in the Keychain on iOS; the `YouTubeAPIKey` Info.plist entry in this repo is
  a dev convenience and the README says so out loud.

## 4. 🟡 Keyless metadata: Piped and Invidious (the "no Data API" answer)

Both are open-source front ends that proxy YouTube and expose JSON. **Piped** is the one
this repo implements, because its search response contains everything the deck needs in a
single call.

Base URL is per-instance. `ios/LofiGlass/Services/PipedProvider.swift` ships a rotating list
and a dead-list:

| instance | status in this repo | note |
| --- | --- | --- |
| `pipedapi.kavin.rocks` | tried first — **fetch failed from this sandbox** | canonical, heavy load |
| `piped-api.privacy.com.de` | in the rotation | community |
| `piped-api.adminforge.de` | in the rotation | community |
| `pipedapi.leptons.xyz` | in the rotation | community |
| `piped-api.lunar.icu` | **quarantined** (observed dead) | instances die weekly; `InstanceRotator` skips these for 10 min |

`GET {base}/search?q=lofi+hip+hop&filter=music` →

```jsonc
{ "items": [ {
    "url": "/watch?v=P31G_H6domU",        // ← id parsed out of here
    "title": "lofi hip hop radio 📚 - beats to relax/study to",
    "thumbnail": "/vi/…",                 // ← absolutised to i.ytimg.com
    "uploaderName": "Lofi Girl",
    "uploaderUrl": "/channel/UC…",         // ← channelId parsed out of here
    "duration": 13022,                    // seconds; 0 == live
    "views": 5_100_000,
    "uploaded": 1_725_000_000_000,         // epoch ms
    "shortDescription": "…#lofi #chill…",  // ← the tracklist + hashtags
    "type": "stream"                       // stream | channel | playlist
} ], "nextpage": "…" }
```

Other Piped routes we touch: `GET /streams/{id}` (description, `chapters`,
`relatedStreams`, and `subtitles`), `GET /comments/youtube/{videoId}` (top comments; the
`nextpage` token is the continuation blob). `filter=music` narrows to music-ish results and
is what makes the whole thing usable for this app.

**Invidious** (`invidious.nerdvpn.de`, `yewtu.be`, `inv.nadeko.net`) has an equivalent
`/api/v1/search?q=…&type=video&sort=relevance` returning `videoId,title,author,authorId,
lengthSeconds,viewCount,published,publishedText,description`, `/api/v1/videos/{id}`, and
`/api/v1/comments/{id}?sort_by=top`. Tested from this sandbox → `401` on the instance we
tried; several public instances now require an account or rate-limit hard, which is why
Invidious is documented here and not implemented — a second half-working front end doubles
the failure surface without adding fields.

Handling rules baked into `PipedProvider` (they came from how flaky the instances are):

- 12 s timeout, decode into `Decodable` DTOs, never hand-parse JSON.
- one retry, next instance; failures quarantined by `InstanceRotator`; **zero** retries.
- raw JSON cached for 10 min (a deck refresh shouldn't re-hit an instance for the same
  query), decoded objects cached for 1 h.
- every track gets `source: .piped` so the UI can badge where it came from.

## 5. 🟡 Keyless metadata that *does* work from a browser: oEmbed

`GET https://www.youtube.com/oembed?url=https://youtu.be/{id}&format=json` →
`{ title, author_name, author_url, thumbnail_url, width, height }`. No key, no quota,
CORS-enabled. It is the cheapest way to **validate and credit** an id you already have, and
it is what `Prototype → refresh metadata` uses when the Data API key is absent. It gives no
duration, no views, no description — so it complements, never replaces.

## 6. The lofi gate — a score you can defend

There is no "lofi" category on YouTube, so acceptance is a weighted regex score over
`title | description | tags | channel` (everything lower-cased, `|·—–` folded to spaces and
padded, so word checks are `contains`). Both implementations share these tables and
`tools/gate-check.mjs` fails if the Swift copy drifts by a single backslash.

**Positive signals** (`+1` extra when the pattern also hits the *title*):

| regex | weight | tag |
| --- | --- | --- |
| `lo[.\-\s]?fi` | 5 | lofi |
| `l o f i`, `ｌｏｆｉ` | 4 | lofi |
| `chill ?hop` | 4 | chillhop |
| `jazz ?hop` | 4 | jazzy |
| `beats? ?to ?(relax\|study\|sleep\|chill\|focus\|drive)` | 4 | beats to … |
| `(music\|beats\|sounds\|tunes\|radio)\s*(to\|for)\s+(relax\|study\|sleep\|focus\|chill\|work\|drive\|code)` | 3.5 | beats to … |
| `study beats`, `sleep lofi`, `lofi girl\|chilledcow` | 3 | study / sleep / lofi girl |
| `instrumental hip ?hop`, `hip ?hop radio`, `boom ?bap` | 3 | instrumental / radio / boom bap |
| `tape hiss\|tape loop\|4th ?gen tape` | 2.5 | tape |
| `24\s*/\s*7`, `\bvhs\b\|crt\|scan ?line`, `chill beats`, `anime (edit\|loop\|amv)`, `type beat` | 2 | vhs / 24/7 / chill / anime edit / type beat |
| `neo soul`, `\bjazzy\b` | 1.5 | neo soul / jazzy |
| `\b(?:prod\.|beat)\s*(?:by\s*)?[a-z0-9_.-]+\b` | 1 | beatmaker |

**Negative signals** (each fires once, on the whole haystack):

| regex | weight | label |
| --- | --- | --- |
| `hard ?style`, `lofi (fake\|filter scam)` | −5 | hardstyle, lofi-bait |
| `deep house`, `progressive house`, `edm (festival\|mix)` | −4 | the impostors that actually show up in "lofi mix" results |
| `subliminal\|affirmation\|solfeggio\|\d{3} ?hz` | −3.5 | frequencies/affirmations |
| `\btrance\b` | −3.5 | trance |
| `phonk`, `binaural`, `karaoke`, `workout\|gym motivation` | −3 | |
| `\bdrill\b`, `k[\s-]?pop` | −2 | |
| `heavy metal\|deathcore\|metalcore` | −5 | metal |

**Context boosts**

- `+2` if the channel is one of 15 whose whole catalogue is curated lofi — `lofi girl`,
  `chilledcow`, `lofi records`, `chillhop music`, `settle`, `the bootleg boy`, `afro lofi`,
  `jeez`, `lofi coffee`, `mimi lofi chill`, `the japanese town`, `a lofi soul`,
  `lofi shop 24h`, `flux.fm`, `lofi corners`.
- `+4` **once** if a title word *starts* with one of 34 producers who only exist in this
  scene — kudasai, no spirit, tonion, nymano, yasumu, hm surf, lilac, trxxshed, jhove,
  blurred figures, another silent weekend, swiftly, hazue, noji, sutton, thymes, home grown,
  luella, idealism, sleep bean, jinsang, fantompower, powfu, dj hazel, luvlee, mnts,
  tenncoats, cwrd, philo, kuun, vanyforce, dthcheese, shimza, purrple cat. A bare
  `Artist - Title` upload with an empty description is exactly the case this covers.

**Duration**

- `+0.75` over an hour (mixes are the point) · `−0.75` under 90 s (clips are noise) ·
  `+0.25` when the duration is 0, i.e. a live radio.

**Accept at ≥ 4.0.** Settings may raise the floor (never lower it); switching the gate off
entirely is the user's decision, made explicitly in the UI.

Eleven mood sets (`sleep`, `study`, `rain`, `cafe`, `night-drive`, `jazzy`, `sad`, `anime`,
`morning`, `code`, `focus`) ride along on the same haystack and feed `track.mood` and the
tag cloud — the gate is one pass, not three.

Deliberately accepted edge case (documented so nobody "fixes" it):
`"Binaural beats for focus • solfeggio 432hz #lofi"` **passes** at 6.0 — the uploader's own
`#lofi` plus a `beats to focus` claim outweigh −3 and −3.5 — while the identical title
without `#lofi` scores 0 and is refused. A hashtag is, in practice, the uploader telling you
the genre; we believe them over our guess.

## 7. Playback, and the boost problem

| route | how | gain control | ToS posture |
| --- | --- | --- | --- |
| **embed** (default) | `WKWebView` hosting `youtube.com/embed/{id}?enablejsapi=1&playsinline=1&origin=…`, driven by the IFrame API | none — cross-origin iframe, no `MediaElementSource` possible; the slider maps onto `setVolume(0…100)` and the app shows what it did | fine: YouTube's own player, our chrome on top |
| **local boost engine** | `StreamLoader` asks **your** resolver `GET {base}/resolve?videoId=` for an audio URL, caches it in `Library/Caches/LoFiAudio`, plays it through `AVAudioEngine` (EQ → +12 dB → varispeed → soft clip → limiter) | real: every dB in the UI is a dB in the audio | **not** YouTube-sanctioned if the samples come from YouTube. That is stated in the app's Settings sheet, the README, and `AppConfig.routeWarning`. The route exists for user-owned files / a self-hosted resolver |

`AppConfig.routeWarning` returns exactly this distinction so the UI can never imply that
+12 dB is live over the iframe.

**Resolver contract** (the only thing a self-hosted server has to implement):

```
GET {resolverBase}/resolve?videoId=P31G_H6domU
Authorization: Bearer <optional token, from Settings>
→ { "url": "https://…/audio.m4a", "expiresAt": 1725000000, "headers": {} }
```

`StreamLoader` dedupes in-flight requests per id, validates the cached file with
`AVAudioFile`, and honours `expiresAt`. It never talks to YouTube directly: whatever
`url` your resolver returns is your responsibility, which keeps the ToS decision in one
place instead of smeared through the app.

## 8. Re-running the probes

From a networked machine (nothing here is required by the app — they are for *verifying*
the 🟡 rows):

```bash
# Piped search + streams
curl -s 'https://pipedapi.kavin.rocks/search?q=lofi+hip+hop&filter=music' | head -c 800
curl -s 'https://pipedapi.kavin.rocks/streams/P31G_H6domU' | head -c 600
for h in pipedapi.kavin.rocks piped-api.privacy.com.de piped-api.adminforge.de; do
  printf '%s ' "$h"; curl -s -o /dev/null -w '%{http_code}\n' --max-time 8 "https://$h/search?q=lofi"
done
# Invidious
curl -s -o /dev/null -w '%{http_code}\n' 'https://invidious.nerdvpn.de/api/v1/search?q=lofi&type=video'
# oEmbed (works from a browser, no key)
curl -s 'https://www.youtube.com/oembed?url=https://youtu.be/m772TdT9uny&format=json'
# Data API — needs a key; check quota too
curl -s "https://www.googleapis.com/youtube/v3/search?part=snippet&type=video&videoCategoryId=10&maxResults=10&q=lofi&key=$YT_KEY"
curl -s "https://www.googleapis.com/youtube/v3/videos?part=snippet,contentDetails,statistics&id=P31G_H6domU&key=$YT_KEY"
curl -s "https://www.googleapis.com/youtube/v3/commentThreads?part=snippet&videoId=P31G_H6domU&order=relevance&maxResults=10&textFormat=plainText&key=$YT_KEY"
```

Then re-run the repo checks — they are the executable spec:

```bash
npm --prefix tools test
#  gate-check.mjs       21/21 seed accepts, 4/4 rejects, 6 adversarial cases,
#                       and byte-for-byte parity of the Swift gate tables
#  seed-schema-check.mjs  every non-optional field in LofiModels.swift exists in
#                       the seed JSON (a missing key = a Decodable crash at boot)
#  project-check.mjs      ios/project.yml parses, source paths exist, Info.plist
#                       keys the code relies on are set
node tools/gate-check.mjs        # GATE OK, exit 0
```

## 9. Failure modes we designed for

| failure | where it shows up | behaviour |
| --- | --- | --- |
| every mirror down | status bar | `feed · seed` badge + one line in the log; deck still plays the 21 seeded discs |
| instance returns a different shape | provider layer | decode error → next instance → seed. Never a crash, never a blank deck |
| quota exhausted | badge turns amber | search disabled for the rest of the UTC day; embed playback and the seed feed keep working |
| comments disabled | info sheet | section renders "no comments (source offline)" and the re-pull button stays |
| video not embeddable | player veil | `🚫 not embeddable — flip the sleeve for credits`; `YouTubeDataProvider` also reads `status.embeddable` before proposing it |
| age/region gated | same veil | same copy; the flipped sleeve still carries the description + tracklist |
| iOS 18/19 (no Liquid Glass) | everything | material-based glass; `#available(iOS 26.0, *)` only for the real `glassEffect` |
| audio file resolution fails | boost sheet | route falls back to embedded, and the reason is printed in the status bar |
